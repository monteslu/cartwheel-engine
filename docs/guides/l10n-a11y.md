# Localization and accessibility

`cartwheel/l10n.h` translates a game: catalogs per locale, fallback chains, CLDR plurals, number and date formatting, pseudo-locales, per-locale fonts and assets. `cartwheel/a11y.h` describes its UI for assistive technology and adds captions, subtitles and input remapping on top of the UI module's text scale, reduced motion and accessible themes.

To add a language to a project step by step, follow the [localization tutorial](tutorial:localize). The reference pages are [l10n.h](header:l10n.h) and [a11y.h](header:a11y.h).

## Catalogs

A catalog (`.cwtr`) holds one locale. It is plain text, a line per entry, so translators and reviewers can diff it. `@` fields describe the locale, `key = value` lines are entries, `key[category]` lines are plural forms, and `#` comment lines right before an entry are its translator note. This is the Arabic catalog of the `l10n_demo` sample:

@include samples/l10n_demo/project/l10n/ar.cwtr

Keys, not source strings, are the ids. Values hold `{name}` placeholders (`{{` and `}}` are literal braces). `@font` names fonts to fall back to while the locale is active; `@direction`, the `@number.*` fields, `@date.*` patterns and `@months` override what the language implies. Catalogs written by the engine or by `cwpack` are canonical (`@locale` first, then the other fields, then entries sorted by key), so a diff shows exactly what changed.

A project file (`.cwl10n`) lists what a game ships: the source and default locales, every catalog, the pseudo-locales to offer, and the assets that have per-locale variants. `cwpack` follows it to the catalogs, the fonts they name and the variant assets.

@include samples/l10n_demo/project/l10n/project.cwl10n

Loading is one call; the locale is chosen with [cw_l10n_set_locale](api:cw_l10n_set_locale), which matches an exact catalog, then the same language (`ja-JP` finds `ja`), then the default:

## Lookup and fallback

The active locale has a chain: its own catalog, its parent tags (`pt-BR` then `pt`), each catalog's `@fallback`, then the default locale. [cw_tr](api:cw_tr) returns the first translation in the chain. A key that no catalog has is *missing*: `cw_tr` returns the key itself, logs it once and counts it, so a typo shows on screen and in [cw_l10n_get_stats](api:cw_l10n_get_stats). [cw_tr_find](api:cw_tr_find) returns NULL instead and counts nothing.

You rarely call `cw_tr` for UI text. Every control translates what it shows through [cw_tr_auto](api:cw_tr_auto) while its `auto_translate` property is on (the default): text that is a catalog key shows its translation, any other text shows as written. Changing the locale re-measures every control. Turn `auto_translate` off on a control whose text the code already translated or formats itself.

Strings from `cw_tr` stay valid until the catalogs are unloaded. Formatted results (plurals, named arguments, numbers, dates) live in the frame arena, until the end of the frame: copy them if you keep them. Everything here runs on the main thread.

## Plurals, numbers and dates

[cw_trn](api:cw_trn) picks the form for a number's CLDR category (`zero`, `one`, `two`, `few`, `many`, `other`, falling back to `other`) and replaces `{n}` with the number formatted for the locale. The rules cover 36 languages and a fallback catalog picks its form with its own language's rule. [cw_trf](api:cw_trf) fills named placeholders, and [cw_l10n_format_number](api:cw_l10n_format_number) and [cw_l10n_format_date](api:cw_l10n_format_date) use the locale's separators, digits and month names. The sample builds its formatted lines from those:

@include samples/l10n_demo/main.c#texts

In Arabic the six counts show six different forms with Arabic-Indic digits, and the date reads `٦ أكتوبر ٢٠٢٦`. Formatting is Gregorian with grouped digits; there are no compact numbers ("1.2K"), other calendars or weekday names.

## Translators' files: PO

Translators often work in gettext PO. The conversion is lossless both ways: `msgctxt` carries the key, `msgid` the source text, `msgstr[i]` the plural forms in the PO language's CLDR order (with a matching `Plural-Forms` header), and `@` fields travel as `X-Cartwheel-*` headers.

```sh
cwpack --po-export l10n/ar.cwtr --po-source l10n/en.cwtr > ar.po
cwpack --po-import ar.po > l10n/ar.cwtr
```

`cwpack` also imports a PO source while packing, from a `roots.txt` line such as `l10n/ja.cwtr = po/ja.po`; the sample's Japanese comes in that way. At run time [cw_l10n_add_po](api:cw_l10n_add_po) loads PO text directly, and [cw_l10n_catalog_to_po](api:cw_l10n_catalog_to_po) / [cw_l10n_po_to_catalog](api:cw_l10n_po_to_catalog) do the conversion in code.

## Pseudo-locales

Offer `en-XA` and `ar-XB` (in the project file or with [cw_l10n_add_pseudo_locale](api:cw_l10n_add_pseudo_locale)) to test layouts before any translation exists. `en-XA` accents every letter, pads the text by 40% and brackets it, so truncated labels and hard-coded (unaccented) strings stand out. `ar-XB` turns the source text right to left and mirrors the UI. Placeholders survive both.

## Fonts, shaping and right to left

Each catalog's `@font` list becomes the global fallback chain when its locale is active, followed by every other catalog's fonts, so a language menu can show each language's name in its own script. A codepoint the UI font lacks comes from that chain at the same size; a codepoint no font has draws the font's missing glyph and counts in the 2D renderer's `glyphs_missing` stat. Keep that stat at 0 in a test.

Text containing right-to-left or complex-shaping codepoints (Arabic, Hebrew, the Indic scripts, Thai and others) is shaped with OpenType joining, ligatures and mark placement, split into bidi runs and reordered per line. Pure left-to-right text never takes that path and costs nothing extra. Wrapping breaks at spaces, and between CJK characters with the common kinsoku rules. See [2D rendering](guide:rendering-2d) for the text API.

In a right-to-left locale the UI mirrors itself: containers and anchors place their children from the right, left and right text alignments swap, and check boxes and option arrows move to the other side. Scroll and split containers, tab bars, trees, sliders, progress bars and text fields keep their left-to-right insides. A control can force a direction with its `layout_direction` property. [cw_l10n_is_rtl](api:cw_l10n_is_rtl) tells game code which way the locale reads.

Font files are large. `cwpack` subsets a font to the characters the catalogs use (plus their number and date output and ASCII) when its import settings say `font.subset = l10n`, keeping glyph ids so the shaping tables stay valid. The sample's Arabic and Japanese fonts ship that way.

Per-locale assets live under `<asset_dir>/<locale>/<path>`; [cw_l10n_asset_path](api:cw_l10n_asset_path) returns the variant for the first locale in the chain that has one, else the path itself. The sample's banner image is a different picture in Arabic and Japanese.

## The l10n_demo sample

[samples/l10n_demo](repo:samples/l10n_demo/main.c) is one settings screen in five locales. Without input it changes every 60 frames: English (frame 50), `en-XA` (110), Arabic (170), Japanese (230), `ar-XB` (290), then English with the accessibility settings on (350). The Arabic screen is fully mirrored, with shaped text and the labels on the right; the Japanese one takes its glyphs from the fallback font and wraps the paragraph between characters. `app.brand` exists only in the English catalog, so every other locale shows it through the fallback chain.

```sh
node tools/run-cart.mjs --host native --app l10n_demo --frames 170 --state out/ar.json --shot out/ar.png
```

`CW_L10N_LOCALE=<tag>` fixes the locale. The gates `l10n-en`, `l10n-pseudo`, `l10n-ar`, `l10n-ja`, `l10n-xb` and `l10n-a11y` compare each screen across hosts, with controls that break one thing each (`CW_L10N_FAULT=missing_key`, `no_fallback`, `no_font`, `no_a11y`). `l10n_nav` is the same sample driven by a scripted gamepad session: it opens the language box, picks Japanese, gets focus back on the box, and rebinds jump on a `RemapButton`.

The `l10n` debug command reports the active locale, its chain and the stats, and answers `l10n locale <tag>`, `l10n tr <key>` and `l10n missing`:

```text
{"locale":"ar","rtl":true,"chain":["ar","en"],"catalogs":3,"keys":76,"missing":0,"fallback_hits":153,...}
```

## The accessibility tree

[cw_a11y_snapshot](api:cw_a11y_snapshot) walks the visible controls of a tree and describes each one an assistive technology cares about: a role from the node type, a name, a value, a description, states (focused, checked, disabled, expanded and so on) and bounds. It is built on demand from the controls, with no retained shadow tree; call it after layout (a frame does that) and do not keep its strings past the frame.

Names come from the control's `accessibility_name`, else its text, else the text of a `Label` right before it in the same container, which is how form rows pair a label with its field. So a grid of label and control rows needs no extra work:

@include samples/l10n_demo/main.c#form

Give `accessibility_name` (it is translated like any text) to controls whose text says nothing, such as the sample's banner image, and `accessibility_description` for longer help (the tooltip is used otherwise). Items inside a control (list items, open popup menu items, tabs) become child entries. Text in the tree is what the user sees: translated and pseudo-localized like the drawing. [cw_a11y_json](api:cw_a11y_json) returns the same as JSON.

The sample hashes the snapshot every frame so the gates can compare it across hosts:

## Events and announcements

Focus changes, value changes (`value_changed`, `toggled` and the like) and live announcements are events. One listener ([cw_a11y_set_listener](api:cw_a11y_set_listener)) hears them as they happen, and the last 64 stay in a ring for pollers ([cw_a11y_events_since](api:cw_a11y_events_since)). [cw_a11y_announce](api:cw_a11y_announce) posts a live-region message such as "Saved", optionally assertive (interrupting what is being read).

The `a11y` debug command serves all of it: `a11y tree`, `a11y focus`, `a11y events <since>`, `a11y announce <text>`, and `a11y set text_scale|reduced_motion|captions|theme <value>`. The `a11y-channel` gate reads the tree, focus, events and l10n state from the native build and from the cart in romdev at the same frame and requires them to be identical.

## Captions and subtitles

A caption track (`.cwcap`) has one cue per line: start and end in seconds, an optional speaker, then the text. Speaker and text are catalog keys or plain text. A cue without a speaker is a sound caption.

@include samples/l10n_demo/project/captions/intro.cwcap

[cw_captions_play](api:cw_captions_play) starts a track. Given a voice, its clock is the voice's played frames, so captions stay in sync with the sound on every host; with a null voice it runs on frame time. [cw_captions_show](api:cw_captions_show) adds a one-off line for barks and effects. The [CaptionPanel](node:CaptionPanel) control draws the active lines with the speaker in its own colour (labelled by [cw_captions_speaker_label](api:cw_captions_speaker_label): the catalog key `caption.speaker_label`, a pattern such as `{speaker} :` for French, else `{speaker}:`), or a game draws them itself from [cw_captions_active](api:cw_captions_active). Captions announce themselves as accessibility events. [cw_captions_set_enabled](api:cw_captions_set_enabled) is the player's subtitles setting: off hides the lines and stops the announcements, and tracks keep their time. The UI module advances captions every frame while the tree has controls; a game without UI calls [cw_captions_update](api:cw_captions_update) itself.

## Settings: text scale, motion, themes, remapping

These live in the UI module ([UI](guide:ui)) and apply to every control:

- [cw_ui_set_text_scale](api:cw_ui_set_text_scale) multiplies every theme font size (0.5 to 4); layouts grow with the text.
- [cw_ui_set_reduced_motion](api:cw_ui_set_reduced_motion) stops caret blink, hover delays and animated UI motion. Games read [cw_ui_reduced_motion](api:cw_ui_reduced_motion) for their own effects: screen shake, parallax, camera bob, flashing.
- [cw_theme_high_contrast](api:cw_theme_high_contrast) and [cw_theme_colorblind](api:cw_theme_colorblind) are built-in themes; a theme file can build on them with `extends = high_contrast` or `extends = colorblind`.
- Every focusable control is reachable by keyboard and gamepad, and closing a popup returns focus to the control that opened it.

@include samples/l10n_demo/main.c#a11y-settings

[RemapButton](node:RemapButton) is a button that shows an input action's binding and, when pressed, captures the next key, button or axis on its device as the new binding. Binding names come from [cw_binding_display_name](api:cw_binding_display_name), translated through the `input.key.*`, `input.pad.*` and `input.axis.*` catalog keys.

## What is not available

Some of this needs code outside the engine or a platform interface that does not exist yet:

- **Screen readers.** The engine produces the tree and the events; it does not talk to AT-SPI, UI Automation, NSAccessibility or ARIA. That bridge is host code, and for carts it needs a wasmcart ABI surface (an accessibility-tree export) that is not defined. Until then, a bridge can follow the `a11y` debug command.
- **The system locale in a cart.** [cw_l10n_system_locale](api:cw_l10n_system_locale) reads the OS preference natively; a cart gets an empty string, because wasmcart has no way to pass the host's locale. Offer a language menu.
- **Text.** No explicit bidi controls (embeddings and isolates), no vertical CJK, Indic text wraps only at spaces, and the caret and selection in text fields stay left to right for RTL text. In a `RichTextLabel`, an LTR phrase of several words inside RTL text reverses its word order. Letter spacing breaks Arabic joining, and there is no kashida justification.
- **Formatting.** No compact numbers, no non-Gregorian calendars, no weekday names.
